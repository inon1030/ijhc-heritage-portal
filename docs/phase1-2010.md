# Phase 1 — 20.10.2026

## Plan (written before implementation)
1. Resolve search IDs across public catalogue sources, intersect words, share predicates between list/count; preserve RLS.
2. URL-backed combined facets with contextual counts, advanced disclosure, removable chips and pagination.
3. Link discrete record values only when another published, catalogued record shares them; batch counts.
4. Hide uncatalogued items from public reads/counts/sitemap; block acceptance without category; expose repair queue to existing experts.
5. Successful readings first, FIFO within groups; unread group with reason and waiting duration.
6. Reversible upload steps, retained edits, replacement confirmation and beforeunload protection.
7. Translated period/origin and field headings; English/Hebrew UI messages written by hand.
8. Add to the archive now / הוסיפו לארכיון עכשיו and FolderPlus in entry points and guide.
9. Add offline unit/component tests, run typecheck/test during work and full verify at end; report limitations honestly.

## Decisions
- Work only here, no git, migrations, network calls, external documentation updates or vault sync (explicit task constraints override project completion instructions).
- Transcript/OCR public search is blocked by existing ai_analyses and transcript-translation RLS (migrations 0002/0024); do not use admin reads to expose searchable private text. Implement public sources and report this part of change 1 as blocked.
- Discrete registry fields mean facet/enum only; text, notes and precise dates never become links.
- Public facet counts will be contextual to the other selected filters, avoiding empty offered combinations.
- Life OS tool discovery was unavailable; no external state is written under the task's local-only constraint.

## החלטות מימוש
- החיפוש מפרק לרשימת מילים ייחודיות; איחוד המקורות לכל מילה וחיתוך בין המילים שומרים על AND גם כשהמילים נמצאות בשדות שונים.
- מזהי התאמות נקראים בחיבור המשתמש, ללא קריאה מיוחסת של OCR או תמלילים, כדי לא לחשוף טקסט פרטי דרך עצם ההתאמה.
- החיפוש משתמש ב-likeTerm ובנוסף מצטט את ערכי OR לפי תחביר PostgREST, כדי שסימני פיסוק לא ייצרו תנאי שאילתה חדשים.
- קריאת מקורות בעמודים של 500 מונעת חיתוך שקט במגבלת PostgREST; קריאת רשומות לפי מזהים באצוות של 100 מונעת כתובות בקשה ארוכות.
- מסלול הבית ללא מסננים שומר על ספירת DB מדויקת וקריאה מוגבלת, ואינו טוען את כל שדות הקטלוג רק כדי להציג מספר.
- המסננים משתמשים במזהי משפחה ובערכי מקור; החלפת שפה אינה משנה את משמעות כתובת החיפוש.
- סוג המדיה נקבע מ-MIME קיים בלבד; MIME שאינו מזוהה אינו הופך למסמך מומצא.
- טווח הפרסום משתמש ב-reviewed_at ובימי UTC, כולל היום האחרון; תאריכים לא תקינים בכתובת אינם מועברים כמסנן.
- רשימות הבחירה נספרות ביחס למסננים האחרים ולחיפוש; ערך ישן מהכתובת נשאר גלוי וניתן להסרה גם כשכבר אין לו התאמות.
- טקסט חיפוש ותאריכים שהמשתמש הקליד עדיין יכולים להחזיר אפס תוצאות; רשימות הבחירה אינן מציעות שילובים ריקים.
- החיפוש לפי תורם נשאר באותו תחום הרשאות: מומחה יכול לראות את החומר המותר לו בבדיקה; המסננים מועברים לשכבת השאילתות.
- רשומות מאושרות ללא קטגוריה נפתחות באותו workbench; שמירת קטלוג משתמשת בפעולת העריכה הקיימת של סטטוס accepted ללא שינוי תפקידים.
- תור הבדיקה מחולק לפי הצלחת הקריאה, לא לפי off_topic; הערת off_topic נשארת בכרטיס ואינה שוברת FIFO.
- חזרה למסך התיקונים אינה מפעילה קריאה נוספת; שינוי טקסט מקדים מאפשר לבחור בין התיקונים הקיימים לקריאה חדשה.
- שינוי קבצים או קיבוץ מחייב קריאה חדשה לפני שימוש בטיוטות הישנות, כדי לא לשלוח תיקונים של קובץ אחר.
- אישור החלפת טיוטות נדרש רק כשיש הבדל מהטיוטות המקוריות; ביטול משאיר את התיקונים נגישים.
- שמות שלבי ההעלאה קצרים כדי להיכנס בשורה בטלפון, והשלב הנוכחי מסומן ברקע בהיר מהטוקנים הקיימים.
- מחרוזות EN/HE נכתבו ידנית; שתי מחרוזות ישנות ב-hi/mr/ml הוסרו יחד עם חותמותיהן כדי ש-resolve יחזיר את האנגלית המעודכנת.
- field VALUES, משפחות, source ומילות מפתח ללא שורת תרגום נשארים בשפת המקור; ההחלטה מתועדת גם בנקודת התצוגה בקוד.
- אין שינוי ב-package.json, במנעול התלויות, ב-access.ts, ב-proxy.ts, במיגרציות או בהרשאות.

## קנה מידה ואינדקסים בהמשך
לכל מילה יש שש סריקות מקורות ומיפוי נוסף ממונחי thesaurus לשמות השמורים ברשומות; אוצר המילים והיטל המסננים משותפים ברמת הבקשה באמצעות React cache. אין שאילתה לכל פריט או לכל תגית מוצגת. קריאת מקורות היא בעמודי 500 והחזרת רשומות באצוות מזהים של 100.

באלפי/עשרות אלפי רשומות יש להוסיף, באישור נפרד, אינדקסי trigram על item_fields.value, item_translations.value, keywords.term, keyword_translations.label ו-families.name; לבדוק EXPLAIN עבור חיבורי משפחות וסינון פרסום. אינדקס search_text הקיים אינו מכסה מקורות אלה. חיפוש משותף עם tsvector/היטל חיפוש מאושר ואגרגציות facets בשרת יחליף אז את איסוף המזהים והספירה בזיכרון. אין כאן מיגרציה או שינוי trigger.
