## 3. איך עובדים איתה

| רוצה ל... | עושים |
|---|---|
| להריץ מקומית | `npm run dev` בתיקיית הקוד. **זה מחובר למסד החי**, אז לא מוחקים ולא מעלים פריטי בדיקה בלי לנקות אחרי |
| לבדוק לפני קומיט | `npm run verify`: טיפוסים, lint, 554 טסטים ו-build. אדום = לא מקמטים |
| לפרוס | יש שני פרויקטים ב-Vercel, ושניהם קוראים מאותו מסד. **האתר הראשי, heritage-portal-snowy.vercel.app**, עולה רק דרך `npx vercel --prod --yes` מתיקיית הקוד. **ijhc-heritage-portal.vercel.app**, בחשבון של העמותה, עולה לבד בכל `git push` ל-`master`. כלומר: דחיפה מעלה את הכתובת השנייה, ואחריה פורסים את הראשית ב-CLI |
| לחזור לגרסה קודמת | `npx vercel rollback --yes` (ראו `docs/RUNBOOK.md`) |
| לשנות את מסד הנתונים | מיגרציה חדשה ב-`supabase/migrations/00NN_*.sql`, מורצת ידנית בעורך ה-SQL של Supabase בתוך `begin; … commit;`, **לפני** הדחיפה של הקוד שצריך אותה |
| להוסיף טקסט למסך | מפתח ב-`src/lib/i18n/messages.ts` (אנגלית) וב-`locales/he.json` (עברית), בכתב יד. `npm run i18n` מתרגם להינדי, מראטהית ומלאיאלאם, ועולה קריאות ג'מיני |
| לטפל בבאג מהעמותה | הסוכן `ijhc-fixer` קורא את הגיליון והמיילים, מתקן בענף `fixes/<id>` ולא פורס. את ההחלטה לפרוס מקבל ינון |
| לעבוד עם Claude Code | לפתוח את התיקייה. `CLAUDE.md` טוען את `AGENTS.md`, ומשם ל-`docs/CODEBASE-GUIDE.md` |
| לחלק עבודה עם Codex | הסקיל `codex-build`: בריף בקובץ `docs/BRIEF-*.txt`, עץ עבודה נפרד לכל סוכן, ו-Claude בודק ומקמט |

2. לא ממציאים נתונים טכניים. מה שלא נמדד מוצג כ"לא נמדד".
3. שינוי ב"מי רשאי מה" עובר דרך ינון ונכתב במסמך ההרשאות.
4. סודות לא יוצאים מהשרת.
5. האתר בהיר בלבד.
